# Phase 1 Implementation Plan: Layer 1 Structural Skeleton (LLM-Free)

## 1. Purpose

Phase 1 delivers a complete Layer 1 Batho Structured Graph (BSG) implementation that is:

- Deterministic and LLM-free.
- Optimized for both agent workflows and human navigation.
- Performance-tuned for large repositories.
- Published as a single parent-level artifact named bsg.json.
- Removes legacy_map.json outputs, legacy_map keys, and legacy_map CLI traces at Phase 1 completion.

This phase explicitly excludes all semantic infusion and LLM enrichment work from Layer 2.

## 2. Scope and Non-Goals

### In scope

1. Full Layer 1 node and relationship coverage from the BSG spec.
2. Rule-plugin driven structural metadata enrichment.
3. Structural indexes optimized for query speed.
4. Output contract rename from legacy_map.json to bsg.json.
5. CLI, metadata, snapshot, and docs migration to bsg naming.
6. Removal of legacy_map compatibility paths, aliases, and metadata keys.
7. Performance optimization and benchmark gates.

### Out of scope

1. Anchor node selection for LLM calls.
2. Semantic summaries, intent, risk tags generated by LLM.
3. Embeddings, vector storage, graph RAG interfaces.

## 3. Current Baseline Summary

The repository already includes:

1. Core graph extraction with entities and relationships.
2. Rule plugin runtime under batho_core/bsg with YAML custom rule support.
3. Rule stage integrated in CodeGraphIndexer.
4. LegacyMap rendering and legacy_map.json output pipeline.

The primary Phase 1 gaps are:

1. Full Layer 1 schema alignment (broader relationship semantics and BSG-first contract).
2. Parent artifact naming and contract migration to bsg.json.
3. Dedicated structural index representation for fast agent/human queries.
4. Performance hardening with measurable gates.

## 4. Target Phase 1 Architecture

## 4.1 Core artifact

Every index operation must produce:

- .ctn/<index_id>/graph.json (raw extraction graph)
- .ctn/<index_id>/bsg.json (parent-level BSG structural artifact)

The bsg.json file is the canonical Layer 1 view for both agents and humans.

{
  "schema_version": "bsg.v1",

## 4.3 Node model in Phase 1

Each node must contain deterministic structural fields only:

1. id
2. type
3. name
4. file
5. start_line
6. end_line
7. signature
8. language
9. scope_tier
10. category
11. service_tag
12. dependency_weight
13. snapshot_id
14. metadata (including bsg.rules tags)

## 4.4 Edge model in Phase 1

Each edge must contain:

1. id
2. source_id
3. target_id
4. type
5. metadata

Relationship type expansion in Phase 1:

1. Existing: CALLS, IMPORTS, INHERITS, IMPLEMENTS, USES, CONTAINS, REFERENCES, DEFINES.
2. Add deterministic structural aliases where derivable without LLM: CALLED_BY, IMPORTED_BY, OVERRIDES.
3. Add deterministic boundary edges where derivable: STACK_BOUNDARY.
4. Keep advanced inference relationships as optional and disabled by default behind config flags.

## 5. Implementation Workstreams

## 5.1 Workstream A: Schema and naming migration

### Goals

1. Introduce bsg.v1 schema version.
2. Retire legacy_map.v1 from active runtime contracts and standardize on bsg.v1.

### File targets

1. batho_core/config.py
2. batho_core/context/schema.py
3. batho_core/context/legacy_map.py (or renamed module if selected)

### Tasks

1. Add BSG schema constant (BSG_SCHEMA_VERSION = bsg.v1).
2. Remove legacy_map schema usage from new runtime contracts and new artifacts.
3. Extend schema exports with BSG-first naming.
4. Remove compatibility loaders and enforce bsg-only keys for Phase 1 outputs.

## 5.2 Workstream B: Parent artifact rename to bsg.json

### Goals

1. Rename index output artifact from legacy_map.json to bsg.json.
2. Remove transitional alias support for legacy_map consumers at Phase 1 completion.

### File targets

1. batho.py
2. batho_core/time_machine.py
3. tests/cli/*
4. tests/test_time_machine.py
5. tests/context/test_bsg_map.py (and follow-up rename to test_bsg_map.py if desired)

### Tasks

1. Write only bsg.json in index flow.
2. Update index metadata outputs key from legacy_map_json to bsg_json and remove legacy_map_json from new entries.
3. Remove legacy_map.json dual-write path and delete write_legacy_map_alias toggle.
4. Snapshot payload migration:
   - New snapshots store bsg field only.
   - Patch and snapshot flows read bsg-only for Phase 1+ snapshots.
5. CLI migration:
   - Introduce batho bsg command.
   - Remove batho legacy_map command and related alias/deprecation path.

## 5.3 Workstream C: Full Layer 1 structural completeness

### Goals

1. Ensure Layer 1 has all deterministic fields from spec.
2. Keep enrichment strictly non-LLM.

### File targets

1. batho_core/context/codegraph.py
2. batho_core/bsg/rules.py
3. batho_core/context/categorizer.py

### Tasks

1. Add deterministic derivation stage for:
   - scope_tier
   - category
   - service_tag
   - dependency_weight
2. Add reversible inverse edges where useful:
   - CALLS -> CALLED_BY
   - IMPORTS -> IMPORTED_BY
3. Add boundary edge generation:
   - STACK_BOUNDARY when service_tag differs on connected entities.
4. Keep all derivations pure and reproducible from code + config only.

## 5.4 Workstream D: Structural indexes for fast traversal

### Goals

1. Materialize query-ready indexes in bsg.json.
2. Avoid repeated O(N) scans in agent/human clients.

### File targets

1. batho_core/context/legacy_map.py (or bsg map module)
2. batho_core/context/codegraph.py

### Tasks

1. Build nodes_by_file index.
2. Build nodes_by_type index.
3. Build nodes_by_scope index.
4. Build nodes_by_category index.
5. Build nodes_by_service index.
6. Build inbound_edges and outbound_edges adjacency maps.
7. Build cross_boundaries list for boundary-focused navigation.

## 5.5 Workstream E: Performance optimization track

### Goals

1. Reduce indexing latency.
2. Improve traversal speed and memory efficiency.

### Mandatory optimizations

1. Path normalization once per entity file, not per rule per pass.
2. Rule matching fast path:
   - Skip glob checks when pattern lists are empty.
   - Pre-lowercase cached values for repeated comparisons.
3. Relationship construction:
   - Dedupe through hashed tuple sets before final list materialization.
4. Index build:
   - Single-pass node and edge aggregation.
   - Avoid repeated dictionary lookups via local references.
5. Serialization:
   - Keep compact fields in bsg.json.
   - Move verbose debug diagnostics behind verbose mode only.

### Optional optimizations

1. Cache parsed glob objects if glob volume grows significantly.
2. Add incremental index patch mode for bsg indexes (parallel to graph patching).
3. Add lazy view generation for full/hierarchical text outputs.

## 5.6 Workstream F: Testing and benchmark hardening

### Functional tests

1. bsg.json exists after index command.
2. New snapshots contain bsg field only (no legacy_map field).
3. Rule pipeline still works for inline and file YAML rules.
4. Index metadata contains bsg_json path and no legacy_map_json key in new entries.

### Performance tests

1. Medium repo benchmark target:
   - Index build <= current baseline + 10% with indexes enabled.
2. Query benchmark target (hot memory):
   - nodes_by_file lookup p95 <= 5 ms
   - one-hop neighborhood lookup p95 <= 20 ms
3. Memory overhead target:
   - <= 1.5x graph-only baseline for full bsg artifact generation.

## 6. Rollout Strategy

## 6.1 Phase 1 Cutover (single release)

1. Generate only bsg.json as the parent artifact.
2. Stop writing legacy_map.json and remove legacy_map_json metadata keys.
3. Switch CLI surface to bsg and remove legacy_map command.
4. Store bsg-only snapshot fields for all new snapshots.

## 6.2 Post-Cutover Cleanup

1. Remove all remaining legacy_map references from docs, tests, and runtime messages.
2. Add CI checks that fail on new legacy_map references.
3. Mark legacy_map contract as removed in release notes and internal docs.

## 7. Definition of Done

Phase 1 is done when all conditions pass:

1. Layer 1 structural fields and deterministic relationships are fully emitted in bsg.json.
2. No Layer 2 or LLM enrichment code is required for any Phase 1 output.
3. batho index writes bsg.json and metadata references it as canonical.
4. Snapshot and patch flows are bsg-only for Phase 1 outputs (no legacy_map fallback).
5. CLI exposes bsg command only and contains no legacy_map alias.
6. Functional tests pass.
7. Performance benchmarks meet targets.

## 8. Execution Checklist

1. Add bsg schema version and remove compatibility loaders/helpers.
2. Update index output writer to bsg.json.
3. Update metadata outputs key to bsg_json.
4. Replace legacy_map CLI command with bsg command and delete old command surface.
5. Expand structural derivation and edge completeness.
6. Add query-ready indexes in artifact.
7. Implement and verify performance optimizations.
8. Update tests and docs.
9. Run full regression and benchmark suite.

## 9. Risks and Mitigations

1. Risk: Breaking existing tooling expecting legacy_map.json.
   - Mitigation: explicit breaking-change release notes, repo-wide rename, and CI grep guards preventing reintroduction.
2. Risk: Higher memory use from additional indexes.
   - Mitigation: Compact index format and single-pass builders.
3. Risk: Test instability with timing-sensitive benchmarks.
   - Mitigation: Use percentile windows and repeated benchmark runs.
4. Risk: Naming drift across modules and docs.
   - Mitigation: one-time migration table and grep-based CI checks.

## 10. Migration Table (legacy_map -> bsg)

1. legacy_map.json -> bsg.json
2. output key legacy_map_json -> bsg_json
3. schema legacy_map.v1 -> bsg.v1 (no compatibility layer)
4. snapshot field legacy_map -> bsg (no fallback)
5. CLI command legacy_map -> bsg (legacy_map command removed)
6. Remove legacy_map traces from runtime logs, docs, tests, and metadata keys
