# Hypergraph Page Implementation Plan

## Context

The dashboard has a stub `hypergraph.js` page ("Coming in Phase 3"). The phase-3 spec
calls for an interactive Cytoscape-based hypergraph with filters, focus mode,
layout switching, and streaming data loading. The user's requirement is:
- **Primary data source:** Use the patchet snapshot (or latest available snapshot) to render the graph.
- **Fallback data source:** If no snapshot is present, load `graph.json` and `bsg.json` from the active index.

## Data Source Strategy

### 1. Snapshot-first approach
- Load the patches index via `loadPatchesIndex()`.
- Sort patches by timestamp DESC, take the latest patch's `newSnapshotId`.
- Load it via a new `loadSnapshotJson(snapshotId)` loader that fetches `snapshots/{id}.json` from the bridge.
- Extract `entities[]` and `relationships[]` from the snapshot JSON.

### 2. Index fallback
- If no snapshots exist, fall back to `loadGraph(indexId)` → reads `graph.json`.
- Additionally load `loadBsg(indexId)` → reads `bsg.json` for rule/tag overlays.
- `loadBsg` is currently a stub (`throw NotImplementedError`); it needs a real implementation.

### Step 4: Hypergraph Page (`hypergraph.js`)

Core implementation:

```js
export async function renderHypergraph(params) {
  const container = createGraphLayout();     // sidebar + canvas + progress
  const indexId = getActiveIndexId();
  
  // Data loading strategy: snapshot-first, index fallback
  let graphData = null;
  let bsgData = null;
  
  // 1. Try latest patch's newSnapshotId first
  const snapshotData = await tryLoadLatestPatchSnapshot();
  if (snapshotData) {
    graphData = snapshotData;
  } else {
    // 2. Fallback to index graph.json + bsg.json
    graphData = await loadGraph(indexId);
    bsgData = await loadBsg(indexId).catch(() => null);
  }
  
  // Boot Cytoscape with data
  const cy = bootCytoscape(canvasEl, graphData, bsgData);
  
  // Apply URL params: focus, kinds, edgeKinds, tags, rules, path, layout
  applyParams(cy, params);
  
  return container;
}
```

## Key Design Decisions

1. **Snapshot selection:** Load the patches index, sort patches by timestamp DESC, take the latest patch's `newSnapshotId` as the primary snapshot. If no patches exist or `newSnapshotId` is missing, fall back to `graph.json` + `bsg.json`.

2. **BSG overlay:** When `bsg.json` is available, use `entityTags` for tag filtering and `rules` for rule filtering. When only snapshot data is available, these filters are hidden.

3. **Cytoscape vendored:** Already exists at `vendor/cytoscape/cytoscape.min.js`. Use the UMD shim pattern to import as ES module.

4. **Performance:** `hideEdgesOnViewport: true`, `textureOnViewport: true`, labels hidden below zoom 0.6. Layout runs only after full data load.

5. **No drawer component yet:** Need to create a reusable drawer in `shared/components/`. The Phase 2 files page will reuse it.

## Acceptance Criteria

- [ ] `#/hypergraph` loads with a progress bar that reaches 100%
- [ ] When patches exist, graph loads from the latest patch's `newSnapshotId`
- [ ] When no patches exist, graph loads from `graph.json` + `bsg.json`
- [ ] All entity kinds and edge kinds appear as filter chips with counts
- [ ] Filters compose (kinds + edge kinds + path glob)
- [ ] `#/hypergraph?focus=<id>` isolates node + neighbours
- [ ] Tapping a node opens the drawer with entity detail
- [ ] Layout switcher changes layout (cose, breadthfirst, concentric)
- [ ] Pan/zoom stays at ≥ 30 fps
- [ ] Reduced motion disables flowing animation
- [ ] URL state persists on back/forward navigation
