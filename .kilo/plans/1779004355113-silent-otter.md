## Phase 1: Fix Node Click & L2 Navigation Bugs (Critical)

**Diagnostic approach**: Implement all defensive fixes in parallel to cover every possible failure mode — duplicate event handlers, data validation, path matching, and error recovery — since the exact root cause is uncertain at runtime.

### 1.1 — Eliminate duplicate event handlers causing double-fire

**Problem**: `hypergraph.js:420-421` registers both `tap` and `click` on nodes, and same for edges (425) and background (441). In Cytoscape 3.x, `tap` is the unified pointer event that fires for both mouse and touch. Desktop mouse clicks trigger `onNodeTap` twice per click — once from `tap`, once from `click`. This double-fires `setFocusNode()` + `router.navigate()`, potentially causing visual flicker, race conditions in the router, or the second call operating on a partially-torn-down Cytoscape instance.

**Fix** (`hypergraph.js:401-444`):
- Remove ALL duplicate `click` event registrations (lines 421, 425, 441). Cytoscape's `tap` event already handles both mouse and touch natively.
- Add a navigation guard to prevent re-entry:
  ```js
  let _navigating = false;
  function onNodeTap(evt) {
    if (_navigating) return;
    const data = evt.target.data();
    const id = data.id;
    if (!id) return;
    _navigating = true;
    setFocusNode(id, evt.cy);
    if (_currentLevel === 1) {
      const targetRoute = data.file || id;
      router.navigate('/hypergraph/file/' + encodeURIComponent(targetRoute));
    } else if (_currentLevel === 2) {
      router.navigate('/hypergraph/node/' + encodeURIComponent(id));
    } else {
      if (id !== _currentTarget) {
        router.navigate('/hypergraph/node/' + encodeURIComponent(id));
      } else {
        showNodeDrawer(data);
      }
    }
    setTimeout(() => { _navigating = false; }, 300);
  }
  ```
- Same pattern for `onEdgeTap` and `onBackgroundTap`
- Wire cleanup to reset `_navigating = false` in the route-change teardown

### 1.2 — Add node data validation before navigation

**Problem**: If node data is missing `id`, `file`, or other expected fields, navigation silently fails or navigates to broken routes.

**Fix** (`hypergraph.js:401-419`):
- Validate `data.id` existence before `setFocusNode` (already partially done at line 405)
- For L1→L2: validate `data.file || data.id` is non-empty; fall back to `data.id`; warn if both empty
- For L2→L3: validate `data.id` resolves to a known node in `_bsgData.nodes`; warn if not found
- Add `console.warn('[batho] Node navigation: missing data')` for debugging
- For L2→L3: if node is not found in `_bsgData`, show inline toast notification instead of navigating to an empty L3

### 1.3 — Fix L2 file path matching in `buildFileSubgraph`

**Problem**: The file path from the node's `data.file` attribute (used in L1→L2 navigation) may not exactly match the path stored in BSG data due to normalization differences (leading `./`, trailing slashes, case sensitivity on different OS).

**Fix** (`bsg-projections.js:244-274`):
- Add fuzzy file path matching algorithm:
  1. Try exact match (existing behavior)
  2. Strip leading `./` or `/` from both sides, retry
  3. Normalize path separators (`\` → `/`), retry
  4. Try suffix match: check if any file path ends with the target or vice versa
  5. Return `{ nodes, edges, file: canonicalPath, matchType: 'exact'|'normalized'|'suffix'|'none' }`
- Cache the canonical path mapping in the bsg object for subsequent lookups

**Fix** (`hypergraph.js:465-478`):
- After `buildFileSubgraph`, check `matchType`:
  - `exact` → proceed normally
  - `normalized`/`suffix` → proceed but show a subtle banner: "Matched canonical path: {path}"
  - `none` → show the improved missing-file panel (see 1.4)

### 1.4 — Improve `renderMissingFilePanel` error recovery

**Problem**: When L2 returns no nodes, the user sees a dead-end error panel with no way to investigate.

**Fix** (`hypergraph.js:1131-1155`):
- Replace the static error panel with a recovery panel:
  - Show the attempted path
  - "Search files" input that filters `_bsgData` file list in real-time
  - List of up to 10 closest matching files (by Levenshtein or common suffix)
  - Each match is a clickable button that navigates to the correct L2
  - "Back to Files" button (existing)
  - "Open in Files page" button (existing)

## Phase 2: Progressive Loading & Performance Optimization

### 2.1 — Implement progressive element loading for large graphs

**Problem**: For large BSG datasets, all elements are added to Cytoscape at once, causing jank during layout computation.

**Fix** (`hypergraph.js:448-509`):
- For L1 with >500 file nodes: batch-add elements in chunks of 200 using `requestAnimationFrame`
- Show incremental progress as elements are added
- Run layout only after all elements are added

### 2.2 — Virtualize L2 node rendering for large files (dual approach)

**Problem**: The L2 budget check (`L2_NODE_BUDGET = 2000`) shows a hard error for large files with no recovery.

**Fix** (`hypergraph.js:473-478` + new functions):
- Replace the hard block with a dual-mode rendering strategy:

**Mode A: Clustered (default for files >2000 nodes)**
- Group nodes by type (CLASS, FUNCTION, METHOD, INTERFACE, etc.) into compound parent nodes
- Each compound node shows: type icon, type name, member count
- Clicking a compound node expands it in-place to show its children
- Edge aggregation: inter-cluster edges show aggregated weight
- Toggle in sidebar: "View: Clustered | Full"

**Mode B: Paginated (user-selectable alternative)**
- Load the first 500 nodes initially
- Show a "Load More" control at the bottom of the sidebar
- Each subsequent batch adds 200 nodes with animated layout re-computation
- Progress indicator shows "Showing 500 / 3,200 nodes"
- "Load All" button with a confirmation for files >5000 nodes

**Shared controls**:
- Sidebar toggle between "Clustered" and "Paginated" modes
- Budget warning panel now shows these options instead of blocking
- Remember user's preference per file in sessionStorage

### 2.3 — Optimize layout computation

**Fix** (`hypergraph.js:936-1007`):
- For COSE layout with >500 nodes: reduce `numIter` to 300, increase `coolingFactor` to 0.97
- Use Web Worker for layout computation if available (Cytoscape doesn't natively support this, so use `setTimeout` chunking instead)
- Add `randomize: true` for large graphs to reduce layout convergence time

### 2.4 — Add rendering performance indicators

**Fix** (`hypergraph.js` + `graph.css`):
- Show node/edge count in the progress bar during loading
- Display render time in the stats bar after layout completes
- Add a "performance mode" toggle that disables animations and hover effects for large graphs

## Phase 6: Error Handling & Resilience

### 6.1 — Add comprehensive error boundaries

**Fix** (`hypergraph.js`):
- Wrap `loadLevel()` in try-catch with user-friendly error display
- Add retry logic for failed BSG fetches (up to 3 retries with backoff)
- Handle Cytoscape initialization failures gracefully
- Show specific error messages for different failure modes:
  - Network failure → "Could not connect to server"
  - Missing artifact → "Run `batho scan` to generate graph data"
  - Parse error → "Graph data is corrupted"
  - Empty graph → "No graph data available"

### 6.2 — Add offline/degraded mode

**Fix** (`hypergraph.js`):
- If BSG data fails to load, check sessionStorage cache
- If cache exists and is stale (< 24h), use it with a staleness warning
- If no cache, show a minimal help screen with instructions
